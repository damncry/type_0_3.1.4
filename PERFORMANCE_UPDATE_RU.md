# type_0 3.1.4 — обновление производительности

## Что изменено

1. **CPU/RAM опрашиваются независимо от интерфейса.** Отдельный Python-поток берёт показатели с интервалом настройки, а React получает кешированный снимок.
2. **Сканирование процессов вынесено из hot path.** Список процессов обновляется примерно раз в 2.5–4 секунды, а не при каждом опросе графика. Получение пути EXE отложено до фильтрации по имени и пользователю.
3. **Снижена нагрузка на pywebview bridge.** Неизменившиеся samples и таблица процессов не сериализуются заново каждый короткий опрос.
4. **График обновляется по версии измерения.** Frontend опрашивает кэш часто, но повторный ответ с тем же metricVersion/sampleVersion не вызывает React setState.
5. **Перетаскивание окна стало режимом низкой нагрузки.** При нажатии на drag-region отключаются polling UI, тяжелые motion transform/layout animations и backdrop blur. После отпускания мыши polling немедленно возобновляется. Python также пропускает дорогое сканирование процессов во время взаимодействия с окном. Есть failsafe 15 секунд, чтобы опрос не оставался на паузе навсегда при потере события mouseup.

## Проверено в рабочей среде разработки

- Python: `py_compile` для `desktop_backend.py`, `core_backend.py`, `webview_main.py`.
- TypeScript/TSX: синтаксическая транспиляция всех 21 файлов без синтаксических ошибок.
- Backend smoke test: начальный снимок, получение повторных кешированных снимков, обновление metricVersion/sampleVersion, включение/выключение window interaction.
- Кешированный `get_snapshot()` вызван 4 раза практически мгновенно на локальном тестовом окружении; новый снимок появился после очередного фонового интервала.

## Ограничения

Это не полная сборка Windows EXE и не измерение FPS на реальном ПК. Нативное поведение PyWebView/WebView2 при перемещении и нагрузка графики всё ещё требуют проверки на Windows.
