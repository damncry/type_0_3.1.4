# type_0 3.1.4

`type_0` is a local Windows system-monitoring desktop application. The user interface is built with React/Next.js and exported as static files. A Python `pywebview` host exposes a local bridge to Windows/psutil features.

## Интерфейс

Внешний вид и React-компоненты перенесены из предоставленного архива пользовательского интерфейса. Демонстрационный источник использует фиктивные данные только в обычном браузере; собранная Windows-версия подключает реальное состояние системы через локальный `pywebview` API.

## Возможности

- Мониторинг ОЗУ и CPU, график текущего сеанса.
- Список процессов текущего пользователя, очистка рабочих наборов и подтверждённое завершение выбранных процессов.
- Необязательная автоочистка по порогу ОЗУ и пауза во время игр.
- Обратимые пользовательские твики реестра с резервной копией.
- Очистка временных файлов, история CSV, пользовательский фон.
- Сохранение настроек, ярлык автозагрузки, значок трея.
- Верхняя панель и frameless-оболочка Windows.

Приложение не использует облачный сервис во время работы. В обычном браузере `npm run dev` показывает демонстрационные значения; для настоящих показателей и системных действий нужна Windows-сборка.

## Сборка

1. Установи 64-битный Python 3.12 (рекомендуется), 3.11 или 3.13.
2. Установи Inno Setup 6, если нужен установщик.
3. Распакуй ZIP полностью в локальную папку, например `C:\Build\type_0`.
4. Запусти `build_exe.bat`.
5. Если Node.js не найден, сценарий скачает портативную Node.js 22 LTS в `.build_tools` из официального источника и проверит SHA-256 архива. Node.js не устанавливается в систему и не входит в конечный type_0.
6. Найди приложение в `dist\type_0\type_0.exe` и установщик в `installer_output\type_0_Setup_3.1.4.exe`, если установлен Inno Setup.

Для первой сборки нужен интернет, чтобы загрузить Python-пакеты и npm-зависимости. Если сеть заблокирована, установи Node.js 22 LTS вручную с https://nodejs.org/en/download и повтори сборку.

## Если запускали run_app.bat до сборки

`run_app.bat` теперь проверяет, существует ли `out\index.html`; если нет, он вызывает полный сценарий сборки вместо того, чтобы просто сообщить об отсутствующей UI-папке. После сборки он проверяет наличие `pywebview` и нужных библиотек перед тихим запуском.

Для диагностики используй `run_app_debug.bat`, который выводит ошибку в консоль. Лог приложения находится в `%APPDATA%\type_0\crash.log`.

## Безопасность

- Не отключай Microsoft Defender и не добавляй папку проекта в исключения ради сборки.
- Не восстанавливай файл из карантина вслепую. Сохрани имя угрозы и путь; возможное ложное срабатывание можно направить Microsoft на проверку.
- Твики реестра явные, обратимые и работают в пользовательском разделе реестра.
- Завершение процессов ограничено доступными процессами текущего пользователя и исключает известные системные процессы.
- Очистка рабочих наборов не завершает приложения и не гарантирует долговременное увеличение свободной ОЗУ.
- В архиве исходников нет готового EXE/Setup: бинарные файлы собираются локально.

## Пути

- Настройки, журнал и резервная копия реестра: `%APPDATA%\type_0`
- Копии пользовательских фонов: `%APPDATA%\type_0\backgrounds`
- Журнал ошибок: `%APPDATA%\type_0\crash.log`
- Портативный Node.js для сборки: `.build_tools` (можно удалить после сборки, если больше не собираешь проект)


## Если Node.js подготовился, но сборка не продолжается

Запускай именно `build_exe.bat`, а не `setup_node.ps1`: последний только скачивает и распаковывает Node.js. В `build_exe.bat` версия 3.1.4 после этого печатает версии Node/npm, проверяет связь с npm registry, устанавливает JS-зависимости, собирает интерфейс и затем упаковывает приложение. Если остановилось на npm, открой `.build_tools\npm-cache\_logs` и пришли самый свежий лог.


## 3.1.4 — точность обновления и плавность окна

- Сэмплирование CPU/RAM перенесено в отдельный Python-поток с устойчивым интервалом.
- Перечисление процессов вынесено в отдельный фоновый поток (обычно раз в 2.5–4 секунды), а не блокирует каждый запрос UI.
- Повторные снимки отдают кэш; список процессов и история передаются в UI только при изменениях.
- График и метрики обновляются при новой версии сэмпла, а не на каждом пустом опросе.
- Во время перетаскивания/двойного щелчка по области заголовка UI-поллинг и скан процессов временно приостанавливаются; затем обновления сразу возобновляются.


## Практическая проверка обновления данных

- CPU/RAM собираются отдельным рабочим потоком раз в 1/2/3/5 секунд согласно настройке; вызов `get_snapshot()` читает последний кэш и не блокирует UI ожиданием чтения системы.
- Список процессов обновляется отдельным потоком раз примерно в 2.5–4 секунды, а в JSON-ответ попадает только после нового сканирования.
- Во время перетаскивания заголовка polling интерфейса временно приостанавливается, а анимации Motion переводятся в reduced-motion режим; телеметрия продолжает собираться в фоне.
